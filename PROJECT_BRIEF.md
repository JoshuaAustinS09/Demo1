# 5. SISTEM PEMESANAN

## Ordering Concept

Gunakan sistem **Shopping Cart + WhatsApp Click to Chat**.

Tujuan sistem: - Memungkinkan pengunjung memilih lebih dari satu menu. -
Mengatur kuantitas item. - Melihat ringkasan pesanan. - Menghitung
subtotal. - Mengirim ringkasan pesanan melalui WhatsApp.

Sistem ini tidak memproses pembayaran dan tidak menyimpan transaksi ke
server.

## Customer Ordering Workflow

Ikuti alur berikut:

1.  Pengunjung membuka website.
2.  Pengunjung melihat menu dan kategori.
3.  Pengunjung menambahkan menu ke shopping cart.
4.  Pengunjung dapat mengubah kuantitas atau menghapus item.
5.  Website menghitung subtotal secara otomatis.
6.  Pengunjung menekan tombol Checkout via WhatsApp.
7.  Website membuat pesan berisi ringkasan pesanan.
8.  Browser membuka WhatsApp melalui Click to Chat.
9.  Pengunjung memeriksa dan mengirim pesan secara manual.
10. Admin restoran mengonfirmasi pesanan melalui WhatsApp.

## Shopping Cart Requirements

Fitur wajib: - Add to Cart. - Increase quantity. - Decrease quantity. -
Remove item. - Menampilkan jumlah item. - Menampilkan subtotal setiap
item. - Menampilkan total subtotal. - Empty cart state. - Checkout
button. - Cart drawer atau panel yang nyaman digunakan pada mobile dan
desktop.

Ketentuan: - Kuantitas tidak boleh kurang dari satu. - Item yang tidak
tersedia tidak dapat ditambahkan. - Subtotal dihitung dari harga
dikalikan kuantitas. - Total dihitung dari seluruh subtotal item. -
Jangan menambahkan biaya pengiriman, pajak, atau biaya layanan jika
belum dikonfigurasi. - Gunakan format mata uang Rupiah. - Cegah item
yang sama muncul sebagai baris terpisah jika seharusnya kuantitasnya
digabung. - Cart harus memiliki feedback visual ketika item ditambahkan
atau dihapus. - Jika cart kosong, checkout harus dinonaktifkan atau
tidak ditampilkan sebagai tindakan aktif.

## WhatsApp Click to Chat

Gunakan format resmi WhatsApp Click to Chat:

`https://wa.me/PHONE_NUMBER?text=ENCODED_MESSAGE`

Ketentuan: - Nomor harus menggunakan format internasional tanpa tanda
`+`, spasi, atau tanda baca. - Nomor WhatsApp harus dikelola melalui
file konfigurasi. - Pesan harus di-encode dengan benar. - Pesan mencakup
nama brand dan ringkasan item. - Setiap item mencakup nama, kuantitas,
harga satuan, dan subtotal. - Cantumkan total subtotal. - Jangan
mengklaim bahwa pesanan telah diterima hanya karena WhatsApp terbuka. -
Pengunjung harus mengirim pesan secara manual. - Jika nomor WhatsApp
belum tersedia, gunakan placeholder konfigurasi dan jangan mengarahkan
pengunjung ke nomor fiktif.

Contoh format pesan:

Halo Maison Kitchen!

Saya ingin melakukan pemesanan:

1.  Creamy Mushroom Pasta Qty: 2 Harga: Rp45.000 Subtotal: Rp90.000

2.  Iced Caramel Latte Qty: 1 Harga: Rp28.000 Subtotal: Rp28.000

Total Subtotal: Rp118.000

Mohon informasi lebih lanjut mengenai pesanan saya. Terima kasih!

Pesan di atas hanya contoh format. Nilai harus dibuat secara dinamis
berdasarkan isi cart.

-   Gunakan whitespace untuk membentuk hierarki.
-   Pastikan menu mudah dipindai.

## Responsive Design

Website harus bekerja dengan baik pada: - Smartphone. - Tablet. -
Desktop.

Target pengujian minimum: - Mobile: 375px. - Tablet: 768px. - Desktop:
1440px.

Ketentuan mobile: - Tidak ada horizontal overflow. - Typography mudah
dibaca. - Spacing disesuaikan. - Tombol mudah disentuh. - Menu kategori
dapat digunakan dengan nyaman. - Cart mudah dibuka dan digunakan. -
Navigation menyesuaikan ukuran layar. - Gambar menyesuaikan container
tanpa distorsi. - Harga dan CTA tidak terpotong. - Layout tidak sekadar
mengecilkan tampilan desktop.

## Micro-interactions

Gunakan interaksi ringan: - Button hover effects. - Smooth
transitions. - Subtle scroll reveal. - Interactive navigation states. -
Cart feedback. - Quantity controls. - Category filter transitions.

Animasi harus meningkatkan pengalaman pengguna, bukan mengganggu.

Hormati preferensi `prefers-reduced-motion`.

## User Feedback

Setiap interaksi penting harus memberikan feedback yang jelas,
misalnya: - Item berhasil ditambahkan ke cart. - Kuantitas berubah. -
Item dihapus. - Cart kosong. - Menu tidak tersedia.

Jangan menggunakan alert browser untuk setiap interaksi jika feedback
inline atau toast sederhana lebih sesuai.

# 9. HOSTING & DEPLOYMENT

Website akan di-host menggunakan **GitHub Pages dengan tipe Project
Site**.

URL yang direncanakan:

`https://USERNAME.github.io/REPOSITORY-NAME/`

Nama repository dan username GitHub harus dikonfirmasi sebelum

## Ketentuan Wajib

1.  Website harus sepenuhnya kompatibel dengan GitHub Pages.
2.  Website harus dapat di-deploy sebagai static website.
3.  Tidak boleh membutuhkan backend server.
4.  Jangan menggunakan database atau server-side functionality.
5.  Semua asset harus menggunakan path yang kompatibel dengan GitHub
    Pages.
6.  Hindari penggunaan absolute path yang menyebabkan asset gagal dimuat
    pada Project Site.
7.  Pastikan seluruh file asset dapat dimuat setelah deployment.
8.  Jika menggunakan build tool, pastikan output build memiliki
    `index.html` pada direktori deployment.
9.  Siapkan deployment menggunakan GitHub Actions jika build process
    memerlukannya.
10. Website harus dapat di-deploy ulang ketika terdapat perubahan pada
    branch utama.
11. Jangan menyimpan API key, password, token, atau informasi rahasia di
    repository.
12. Jangan menganggap deployment berhasil sebelum URL production
    benar-benar diuji.

Jangan mengasumsikan username atau nama repository. Buat konfigurasi
yang mudah diperbarui.

mengarah ke pihak nyata. - Jika informasi belum tersedia, gunakan
placeholder yang jelas. - Jangan menyebarkan informasi bisnis yang sama
di banyak file. - Perubahan konfigurasi harus dapat dilakukan tanpa
mengubah banyak komponen UI.

# 11. CONTENT & LANGUAGE

Bahasa utama website adalah **Bahasa Inggris** untuk konsep visual
Maison Kitchen yang konsisten dengan brand demo.

Ketentuan: - Gunakan bahasa Inggris yang natural dan mudah dipahami. -
Copywriting harus hangat, singkat, dan berorientasi pada pengunjung. -
Nama menu dapat menggunakan nama makanan yang umum. - Harga menggunakan
format Rupiah (IDR). - Jangan menggunakan jargon yang tidak

diubah ke Bahasa Indonesia tanpa perlu mengubah struktur teknis utama.

# 12. MENU DATA MANAGEMENT

Buat sistem pengelolaan data menu yang mudah diperbarui.

Setiap item menu minimal memiliki: - ID. - Name. - Category. -

label.

Ketentuan: - Simpan data menu pada satu sumber data. - Gunakan ID unik
untuk setiap menu. - Harga harus berupa angka. - Kategori harus
menggunakan nilai yang konsisten. - Featured menu mengambil data dari
sumber data yang sama. - Menu yang tidak tersedia tidak dapat
ditambahkan ke cart. - Pastikan perubahan harga otomatis tercermin pada
menu dan cart. - Jangan menulis data menu secara terpisah pada banyak
komponen.
